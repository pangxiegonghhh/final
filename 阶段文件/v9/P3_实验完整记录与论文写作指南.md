## 二、假设验证总结

### H-D1 成立：路由显著优于随机

两域、两种特征均显著优于随机选 prompt。Embedding 路由在 SQuAD 上优势更明显（+4.4 点，p=0.0001）。

### H-D2 域依赖性结论：

- **SQuAD 上成立**：Route-Top1 (embedding) 与 Best-Single **统计等效**（p=0.70），说明路由器在无需域先验知识的情况下，自动选 prompt 可以匹敌人工选择。
- **CCNews 上不成立**：Route-Top1 仍显著低于 Best-Single（-2.7 点，p=0.0008）。原因：CCNews 各 prompt 间性能差异小（P1 波动仅 0.063），路由器难以学到有效的 prompt 选择边界。

### H-D3 域依赖性结论：

- **SQuAD 上成立**：Route-Top2 (embedding) 与 Ens-Top3 **统计等效**（p=0.14），以成本=2 匹敌成本=3 的固定子集。
- **CCNews 上不成立**：Route-Top2 显著低于 Ens-Top3（-3.3 点，p<0.0001）。

### H-D4 强烈成立：路由理论上界极高

Oracle-Top1 在两域均达到 0.99+，证明"每条样本确实存在一个最适合的 prompt"。实际路由器与 Oracle 的差距（CCNews: 0.77 vs 0.99; SQuAD: 0.73 vs 0.99）指向了明确的未来改进空间。

## 三、核心发现（论文亮点）

### 发现 1：路由在 SQuAD 上实现了"免费午餐"

Route-Top1 (embedding) 在 SQuAD 上的 F1=0.732，与 Best-Single 的 0.730 无统计差异（p=0.70）。这意味着：**路由器以零额外成本（仅需一次 embedding 计算）替代了需要 P1 敏感性分析才能获得的域特定最佳 prompt 知识**。在实际部署中，这消除了对域先验的依赖。

### 发现 2：Route-Top2 在 SQuAD 上逼近 Ens-Top3

Route-Top2 (0.772) 与 Ens-Top3 (0.779) 无显著差异（p=0.14），成本从 3 降至 2（-33%）。成本-性能曲线上，Route-Top2 填补了 Best-Single 和 Ens-Top3 之间的空白，成为成本=2 档位的帕累托最优。

### 发现 3：Embedding 特征在语义异质域上优势显著

SQuAD（维基百科问答，文本语义多样性高）上 embedding 路由 Top-1 比元特征路由提升了 2.8 个 F1 百分点。CCNews（新闻，文体同质性高）上几乎无提升。这揭示了路由器的特征需求与域特征的关系：**语义异质域需要语义级特征（embedding），语义同质域用简单统计量即可**。

### 发现 4：路由效果具有域依赖性

CCNews 上路由效果有限，根本原因是 P1 阶段发现的"CCNews 各 prompt F1 波动仅 0.063"。当所有 prompt 表现接近时，"选哪个 prompt"的信号本身就弱，路由器难以学到有意义的映射。这不是路由方法的失败，而是域特征对路由收益的天然约束。

### 发现 5：Oracle 上界揭示了巨大的提升空间

Oracle-Top1（0.99+）与实际路由（0.73–0.77）之间的差距表明，更强的路由特征（如微调 embedding、跨域迁移学习）有望进一步缩小这一差距。这为未来工作提供了清晰方向。

### 4.3 各节具体写法

#### 6.1 动机

> "第 5 章的实验表明，多提示词集成可以将检测 F1 提升 10–20 个百分点，但全集成需要 7 次重写（Ensemble-All）甚至额外的一致性特征计算（Ensemble-All+Cons）。在大规模文本审核场景中，每条文本 7 次重写的延迟与成本难以接受。同时，第 4 章的敏感性分析显示，不同样本的最优提示词可能不同——P4_formal 在新闻文本上最优，P5_concise 在百科文本上最优。这自然引出了一个问题：能否训练一个轻量路由器，根据输入文本的特征自动选择 1–2 个最合适的提示词，从而在控制成本的同时保持接近集成的性能？"

#### 6.2 方法设计

**6.2.1 专家与 Oracle**

> "对每个提示词 P_k（k=1,...,7），在训练集上训练一个独立的 LR 专家分类器（5 维 Invariance 特征，与第 3–5 章对齐）。在开发集上，为每条样本 x_i 计算 7 个专家对其真实标签的预测置信度，取置信度最高者为 oracle-best prompt：oracle(x_i) = argmax_k P(y_i | x_i, expert_k)。Oracle 标签构成路由器的训练目标。"

**6.2.2 路由器特征**

> "路由器的输入必须是不需要重写即可获取的低成本特征。本研究对比两种特征方案：（1）元特征（8 维）：词数、平均词长、句数、平均句长、标点率、数字率、大写率、词汇多样性（type-token ratio）；（2）句嵌入（384 维）：使用预训练 Sentence-BERT 模型（all-MiniLM-L6-v2, Reimers & Gurevych, 2019）对输入文本编码。元特征的计算成本几乎为零，句嵌入仅需一次前向传播（约 1ms/样本），两者均远低于一次 LLM 重写的成本。"

**6.2.3 推理流程**

> "路由器输出 7 个 prompt 的概率分布。Top-1 路由选择概率最高的 1 个 prompt，仅用该 prompt 的专家做检测（成本=1 次重写）。Top-2 路由选择概率最高的 2 个 prompt，取两个专家的平均预测概率做检测（成本=2 次重写）。"

#### 6.3 实验结果

**6.3.1 H-D1/D2（最重要的结果段）**

> "如 Table 5 所示，Embedding 路由 Top-1 在两域上均显著优于随机选 prompt（SQuAD: +0.044, p=0.0001; CCNews: +0.011, p=0.046），H-D1 成立。
>
> 更关键的是，在 SQuAD 上，Route-Top1 (embedding) 的 F1=0.732 与 Best-Single 的 0.730 无统计显著差异（t(9)=0.40, p=0.70）。这意味着路由器在无需域特定先验知识的情况下，自动选择的提示词效果等同于通过 P1 敏感性分析确定的域最优提示词。然而在 CCNews 上，Route-Top1 (0.768) 仍显著低于 Best-Single (0.795)（p=0.0008），H-D2 呈现域依赖性。"

给出 **Table 5**（全景总表）。

**6.3.2 H-D3**

> "Route-Top2 (embedding) 在 SQuAD 上 F1=0.772，与 Ens-Top3 (0.779) 无统计显著差异（t(9)=-1.60, p=0.14），但成本从 3 降至 2（-33%）。在 CCNews 上差距较大（Route-Top2 0.818 vs Ens-Top3 0.851, p<0.0001）。H-D3 在 SQuAD 上成立。"

**6.3.3 元特征 vs Embedding**

> "在 SQuAD 上，Embedding 路由 Top-1 较元特征路由提升 2.8 个 F1 百分点（0.732 vs 0.704），而 CCNews 上两者几乎无差异（0.768 vs 0.766）。SQuAD 来自维基百科问答，文本语义多样性高（涵盖历史、科学、地理等多个主题），句嵌入能够捕捉这种语义差异并映射到最适合的提示词；CCNews 的新闻文体同质性高，简单统计量已足够刻画文本特征。"

给出 **Figure 3**（成本-性能曲线，x=成本 1/2/3/7，两域分别画线，标注所有策略）。

**6.3.4 Oracle 上界**

> "Oracle-Top1 在两域均达到 F1≈0.99，远高于实际路由器（0.73–0.77）。这一差距表明，对于大多数样本确实存在一个'最适合'的提示词，但当前路由器的特征表达能力尚不足以精确预测这一选择。Oracle 与实际路由的差距为未来的路由器改进划定了理论空间。"

#### 6.4 分析与讨论

**6.4.1 域依赖性**

> "路由收益的域依赖性可以追溯到 P1 的发现：SQuAD 的跨提示词 F1 波动范围（0.152）远大于 CCNews（0.063）。当不同提示词的性能差异越大，'选对 prompt'的收益就越高，路由器的价值也越大。CCNews 上各 prompt 表现接近，'选哪个都差不多'，路由的边际收益自然有限。这一结果也启示：在实际部署中，路由机制对于文本来源多样化（如混合新闻、百科、学术等多种域）的场景收益更高。"

**6.4.2 帕累托前沿**

> "综合 P1–P3 的全部策略，可以绘制一条清晰的帕累托前沿（Figure 3）：
> - 成本=1：Embedding Route-Top1，无需域先验，SQuAD 上等效 Best-Single
> - 成本=2：Embedding Route-Top2，SQuAD 上等效 Ens-Top3
> - 成本=3：Ens-Top3，稳定提升但需域先验选择 prompt
> - 成本=7：Ens-All+Cons，最高性能（F1≈0.93）
>
> 用户可根据具体场景的延迟预算和准确率需求，在这条帕累托前沿上选择最合适的策略。"

**6.4.3 局限与未来工作**

> "本章的路由器仍存在以下局限：（1）路由器仅在同域内训练和评估，跨域迁移能力未验证；（2）Oracle 与实际路由的巨大差距（0.73 vs 0.99）表明，预训练句嵌入虽优于元特征，但仍非最优的路由特征——微调 embedding 或引入域自适应机制可能进一步缩小差距；（3）路由器的训练依赖 oracle 标签，而 oracle 标签的构造需要所有 prompt 的重写结果，这在初始阶段仍需全量重写。未来可探索 few-shot oracle 构造或在线学习策略。"

## 六、本章结论汇总（方便写摘要和结论章）

1. 提示词路由器在两域上均显著优于随机选 prompt（H-D1 成立），验证了自动选择提示词的可行性。
2. 在 SQuAD 上，Embedding 路由 Top-1 与人工选择的域最优 prompt 统计等效（p=0.70），Route-Top2 与 Ens-Top3 统计等效（p=0.14），实现了以成本=1–2 匹敌成本=1（需先验）或成本=3 的策略。
3. 路由收益具有域依赖性：在 prompt 间性能差异大的域（SQuAD）上收益显著，在差异小的域（CCNews）上收益有限。
4. Embedding 路由特征在语义异质域（SQuAD）上显著优于简单元特征（+2.8 F1 点），在同质域（CCNews）上无明显差异。
5. Oracle 上界（F1≈0.99）与实际路由的差距（0.73–0.77）指向了明确的未来改进方向。
6. 综合 P1–P3 的全部策略，形成了一条完整的成本-性能帕累托前沿，用户可根据场景需求灵活选择。
